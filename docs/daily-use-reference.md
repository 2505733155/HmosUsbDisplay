# 稳定性与日常使用排查参考

本阶段采用用户试用。以下清单保留供问题排查和后续回归时参考。

## 材料

- [项目说明](../README.md)、[USB 验证记录](usb-verification.md)和[任务看板](../workboard.html)。
- Windows 发送端和启动入口位于 `pc/`，鸿蒙接收端位于 `harmony/`。本机 HDC 启动入口位于 `.local/start-subscreen.cmd`。
- 采样、发送端日志、平板解码日志和数字截图存放在 `.local/daily-tests/`。比对证据时仅记录图像中与测试有关的区域和结果。

## 检查项目与验收条件

1. 按 README 构建 Windows 发送端和鸿蒙 HAP。核对公开配置模板和实际忽略规则，确认签名配置、证书、HAP、调试日志和截图在提交范围之外。
2. 核对内存问题的前后对照。只采集与采集加编码的原始测试应可区分内存增长来自哪个环节。检查 `ProcessOutput` 交出的样本与事件引用是否由调用方接管并释放，以及调用方提供的样本是否由原智能指针管理。
3. 检查固定 1920×1080、目标 25 fps 的 USB 连续测试。发送端和接收端应稳定工作至少 30 分钟，帧数与运行时间一致，发送端在预热后无持续内存增长。对照不同时刻的平板画面、发送端统计和解码日志，确认实际显示持续更新。
4. 核对鼠标指针、等比显示与分辨率切换。平板应显示位于虚拟屏上的 Windows 指针。1920×1080 在 2800×1840 平板上应完整显示，视频区域约为 2800×1575。将虚拟屏切换至 2560×1440 后，确认同一块虚拟屏继续存在，发送端用新尺寸握手，平板重新解码。
5. 核对拔插及日常入口。USB 拔出时虚拟屏应回收，插回后平板应自动恢复画面。在相同环境使用 `pc/start-watch.cmd` 或本机入口启动、按 Ctrl+C 停止并重复一次，核对两次退出后的显示器与 HDC 转发状态。如果端口已经存在转发，第二实例应保留既有转发并退出。
6. 使用当前发送端和接收端，给日常入口加 `--touch`。在平板画面内实体点按和拖动，检查 Windows 窗口收到原生触点，且位置与画面一致。从黑边按下再滑进画面，Windows 应无对应触点。保持按住时拔线，检查当前触点释放，重连后可再次点按。以已记录的自动和手动手势日志为对照，分别登记各项实测结果。
7. 切换回默认启动参数，确认画面正常且平板触摸不生成 Windows 输入。在可以使用旧版接收端的环境中，用当前发送端复核默认推流，并确认请求触控时仍可显示画面。没有旧版接收端时，将兼容性记为待核验。
