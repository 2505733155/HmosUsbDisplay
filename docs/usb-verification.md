# USB 扩展屏真机验证

2026 年 11 月 24 日，使用支持数据传输的双头 USB-C 线连接 Windows 11 25H2 电脑与 LRT-W20 平板。平板运行 HarmonyOS 7.0.0.111 SP18（API 26），接收端由 DevEco Studio 26.0.0 生成调试签名。

Windows 在原有两块显示器之外创建了一块 1920×1080 的独立显示器。只在新增显示器上打开带编号的测试窗口，平板截图显示了同一窗口。Windows 端在约 20 秒的测试中发送了 510 帧 H.264，约 25 fps。测试退出后，Windows 恢复原双屏布局，临时 HDC 转发被移除。

这台电脑上的 NVIDIA H.264 编码器激活失败，发送端回退到 Intel Quick Sync。测试期间发送进程的提交内存从约 365 MB 增至约 1.44 GB。长时间运行和拔线重连仍待验证。

## 目录整理后的回归测试

从整理后的目录重建 Windows 发送端和鸿蒙签名包，通过 HDC 将签名包覆盖安装到同一台平板。第一次测试建立了 USB 串流，截图未拍到测试窗口。平板解锁并打开 SubScreen 后再次测试，接收端以 1920×1080 启动解码，平板截图显示了仅放在 Windows 新增显示器上的 `SUBSCREEN 162356` 窗口。

发送端约 14 秒内发送 358 帧 H.264，约 25 fps，退出码为 0。测试后 Windows 恢复原双屏布局，临时 HDC 转发被移除。

基线截图和日志，以及回归测试的截图 `reorganization-usb-proof-162356.jpeg` 和发送端日志 `reorganization-sender-162356.log`，均保存在本机工作区的 `.local/evidence/2026-11-24/`，可用于独立核验。
