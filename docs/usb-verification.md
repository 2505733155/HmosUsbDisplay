# USB 扩展屏真机验证

2026 年 11 月 24 日，使用支持数据传输的双头 USB-C 线连接 Windows 11 25H2 电脑与 LRT-W20 平板。平板运行 HarmonyOS 7.0.0.111 SP18（API 26），接收端由 DevEco Studio 26.0.0 生成调试签名。

Windows 在原有两块显示器之外创建了一块 1920×1080 的独立显示器。只在新增显示器上打开带编号的测试窗口，平板截图显示了同一窗口。Windows 端在约 20 秒的测试中发送了 510 帧 H.264，约 25 fps。测试退出后，Windows 恢复原双屏布局，临时 HDC 转发被移除。

这台电脑上的 NVIDIA H.264 编码器激活失败，发送端回退到 Intel Quick Sync。测试期间发送进程的提交内存从约 365 MB 增至约 1.44 GB。长时间运行和拔线重连仍待验证。

## 目录整理后的回归测试

从整理后的目录重建 Windows 发送端和鸿蒙签名包，通过 HDC 将签名包覆盖安装到同一台平板。第一次测试建立了 USB 串流，截图未拍到测试窗口。平板解锁并打开 SubScreen 后再次测试，接收端以 1920×1080 启动解码，平板截图显示了仅放在 Windows 新增显示器上的 `SUBSCREEN 162356` 窗口。

发送端约 14 秒内发送 358 帧 H.264，约 25 fps，退出码为 0。测试后 Windows 恢复原双屏布局，临时 HDC 转发被移除。

基线截图和日志，以及回归测试的截图 `reorganization-usb-proof-162356.jpeg` 和发送端日志 `reorganization-sender-162356.log`，均保存在本机工作区的 `.local/evidence/2026-11-24/`，可用于独立核验。

## Windows 编码内存复测

在同一台电脑用 1920×1080、25 fps 的虚拟显示器做对照。修正前只运行桌面采集时，12 秒内采集 301 帧，提交内存保持在约 59 MiB。启用 Intel Quick Sync 的 D3D 纹理输入后，提交内存从 363 MiB（50 帧）增至 843 MiB（255 帧）。两组均在 Windows 本机运行，排除了 USB 传输和接收端的影响。

Media Foundation 的 `ProcessOutput` 将编码器提供的样本和事件引用交给发送端。原代码为输出样本增加了一个引用，在作用域结束时释放的是新增引用。修正后直接接管并释放编码器交出的引用，调用方分配的样本仍由原智能指针管理。

重新构建后，用相同参数运行本机采集和编码约 90 秒，共编码 2,212 帧。前几秒从约 247 MiB 降至 244 MiB，直至结束维持在约 244 MiB。本机采样和调试日志保存在 `.local/daily-tests/`。

USB 回归使用同一套修正后的 Windows 发送端。发送端以约 25 fps 编码 460 帧，平板以 1920×1080 解码 459 帧。发送端提交内存预热后维持在约 245 MiB，丢帧统计为 0。测试退出后移除了临时 HDC 转发，Windows 恢复原双屏布局。

## 扩展屏鼠标指针

虚拟显示器位于主屏左侧时，用户报告平板能显示 Windows 画面，但看不到鼠标指针。DXGI 返回相对当前输出的指针图形左上角坐标。旧代码再次减去了屏幕原点和热点偏移，导致超出画面。这次修正直接使用输出内坐标，只在 DXGI 报告指针状态更新时更改可见性和位置，同时按驱动格式合成单色和掩码彩色指针。[Desktop Duplication API](https://learn.microsoft.com/en-us/windows/win32/direct3ddxgi/desktop-dup-api)

本机回归覆盖了位于负坐标的扩展屏、仅更新桌面内容的帧和掩码彩色指针。三项检查在旧版均失败，修正后通过。切换桌面后，用修正后的发送端重新启动真机测试，用户将 Windows 鼠标移到扩展屏并确认平板显示了指针。

## 等比显示与分辨率切换

平板的 2800×1840 屏幕原先把 1920×1080 视频拉伸到四边，图形在水平方向显得偏窄。接收端改用鸿蒙原生窗口的等比适配模式。安装签名包后，数字截图中 16:9 画面占据约 2800×1575 像素，边缘位置符合等比换算，底部黑边和画面内的 Windows 任务栏清晰可辨。

连续运行约 10 分钟时，用户将虚拟显示器从 1920×1080 改为 2560×1440。Windows 端检测到尺寸变化，却连续用旧参数重新连接，最终触发测试的内存保护。修改后，旧采集和编码会话结束，发送端保留同一块虚拟显示器，按实际尺寸重新初始化并发送新握手。

用相同的 1920×1080 到 2560×1440 切换复测，平板按新尺寸启动解码并解码了 662 帧，发送端保持约 25 fps。高分辨率段的提交内存在观测期内约为 592 MiB。测试正常退出，清理了虚拟显示器和临时 HDC 转发。数字截图和日志保存在 `.local/daily-tests/`。

## USB 拔插恢复

拔线后守护模式移除了虚拟显示器。重新插线后，它创建新的虚拟显示器并恢复 1920×1080、约 25 fps 推流，用户确认平板自动出画。重连后该尺寸连续运行约 3 分 42 秒，提交内存稳定在 475–478 MiB，平板解码了 5,448 帧。

随后 Windows 将虚拟屏切换至 2048×1152，发送端按新尺寸重建并完成握手。长测脚本检测到分辨率变化后结束本轮，发送端正常退出并回收虚拟显示器和 HDC 转发。

## 固定分辨率连续运行

在同一台平板保持 1920×1080，目标 25 fps。发送端统计从进入该分辨率到最后一次采样覆盖 30 分 27 秒，896 次采样的平均编码速率为 25.00 fps，预热后提交内存约 326–330 MiB。发送端共编码 45,686 帧，平板解码 45,137 帧。三次平板数字截图的等比显示检查通过，截图上的 Windows 时钟随测试进度更新。发送端正常退出，Windows 恢复原双屏布局，HDC 转发已移除。

采样、日志和截图位于本机 `.local/daily-tests/usb-steady-1738/`。

## 日常启动与退出

用本机一键入口启动、停止，然后重复一轮。两次都创建一个额外显示器并推流，平板分别解码 209 帧和 184 帧。两次都通过控制台停止信号正常退出，收回扩展屏和本次创建的转发。Windows 可能提示确认终止批处理。重复启动与正在使用的 HDC 端口冲突时，新实例退出，原有转发继续工作。

两次启动退出的日志位于本机 `.local/daily-tests/launcher-180957/`。

## 更高帧率的可行性测试

平板的 DisplayManagerService 报告当前显示模式为 2800×1840、60 Hz。Windows 的虚拟显示器刷新率、发送端 `--fps` 目标和平板每秒解码帧数是三个不同指标。下表的平板数据按解码器启动至停止的日志时间计算，显示面板的实际呈现帧率未测量。

本轮 Parsec VDD 接受了创建请求，但 DXGI 没枚举到独立的桌面输出。两次扩展屏测试未进入编码阶段。内屏对照使用临时的 DPI 感知发送端，固定 Intel Quick Sync、约 22 秒、同一条 USB 链路。日志保存在 `.local/daily-tests/rate-*/`。

| 内屏对照输出 | 发送端目标 | 编码帧数 | 平板解码帧数 | 平均解码帧率 |
| --- | --- | --- | --- | --- |
| 1920×1200 | 30 fps | 484 | 417 | 18.9 fps |
| 1920×1200 | 45 fps | 519 | 511 | 22.8 fps |
| 1920×1200 | 60 fps | 535 | 534 | 23.8 fps |
| 1280×800 | 60 fps | 946 | 818 | 36.9 fps |

1920×1200 的 60 fps 对照中，CPU 转换约 34 ms/帧，GPU 缩放帧数为 0。1280×800 的整数降采样约 13 ms/帧，平板解码超过 25 fps，说明较高帧率可以通过当前 USB 链路。对照结果支持继续检查采集和缩放开销。1920×1080 真扩展屏稳定配置仍以此前通过长测的 25 fps 为基线。

## 平板触屏回传可行性

鸿蒙 SDK 提供 XComponent 的原生触摸回调、组件内坐标和触点状态。接收端已有对应回调入口。隔离验证包把按下、移动、抬起和取消记录写回当前 HDC 转发的 TCP 连接，Windows 端只记录并识别手势。等比坐标检查已验证屏幕中心映射到视频中心，并忽略黑边内的触点。Windows SDK 的 `InitializeTouchInjection` 在当前用户下初始化成功，向 Windows 应用注入触控事件尚未验证。

诊断包已签名、安装并通过 USB 建立连接。第一轮等待实体操作超时后恢复了原版。第二轮由用户在平板上实际操作，Windows 收到单指点按和拖动的完整事件序列。映射到 1920×1080 后，点按起止位置为 (173, 373) 至 (173, 372)，画面内拖动为 (207, 346) 至 (1488, 328)。另一次从上方黑边起步的触点未映射到视频区域。诊断结束后移除了转发并恢复原版。原型和 `touch-events-202820.ndjson` 保存在本机 `.local/daily-tests/touch-probe/`。

如果进入正式开发，触点处理应限定在用户明确开启的当前 USB 会话和虚拟屏区域，支持按下、移动、抬起和断线取消。桌面坐标映射还需验证虚拟屏位置、DPI 和分辨率变化。[Windows 触控输入 API](https://learn.microsoft.com/windows/win32/api/winuser/nf-winuser-injecttouchinput)

## Windows 原生单指触控试用

用户在 Win+P 中选择「扩展」后，最初探针仍只看到与内屏共用显示源的 Parsec。后续探针识别到独立的 `DISPLAY32` 并采集成功。加载新版接收端并用 `--touch` 启动后，平板显示了 Windows 测试窗口。手动和自动测试均未让窗口收到原生手势。诊断版日志确认平板写回按下事件，Windows 收到后定位到左侧虚拟屏，但 `InjectTouchInput` 对首个按下返回错误 87。仅把初始化移到输入线程也复现了同样错误。

发送端已试用 `InjectSyntheticPointerInput`，按照其接口约定将触点换算为相对整个虚拟桌面左上角的坐标。本机创建和销毁合成触控设备通过。后续两轮实机测试在虚拟屏就绪后卡在采集初始化，未走到输入验证。平板已恢复原版，临时转发已清理，Windows 已回到单屏。诊断日志存放在本机 `.local/daily-tests/touch-probe/native-*/`。[Windows 合成指针输入 API](https://learn.microsoft.com/windows/win32/api/winuser/nf-winuser-injectsyntheticpointerinput)

用户报告这两轮测试期间 Windows 桌面无法操作，需要重启。事后检查中，Parsec 系统日志在 21:09 和 21:14 均记录了虚拟监视器创建成功。发送端日志停在虚拟屏就绪，早于 D3D11 初始化成功标记和触控线程启动。系统日志记录了异常关机，现有证据无法确定具体哪次图形调用阻塞。发送端已在 `crash_probe.log` 中记录采集初始化阶段的 DXGI 工厂创建、枚举、输出描述和 D3D11 设备创建。重启后完成离线构建和触点协议检查，未再次启动虚拟屏。

用户随后在可中断桌面工作的时段授权复测。三轮记录保存在本机。

| --- | --- | --- |
| 只采集 | 1920×1080 阶段采集 100 帧，虚拟屏正常回收。该模式未编码，退出码 4 对应无编码输出。 | `.local/daily-tests/capture-only-213440/` |

两轮触控测试结束后均恢复了原显示布局并回收测试用 HDC 转发。新版 HAP 保留在平板。本轮未单独实测按住时拔线或旧接收端兼容性。两次历史桌面卡死的根因仍待确认。

## 双指触控

Windows 发送端在启用触控时同时公布单指和双触点帧能力，鸿蒙接收端仅在识别到双触点帧能力后才发送新格式。新版发送端仍接收旧版的单触点消息。每帧包含两个固定槽位的触点状态。手指从画面内按下时才分配槽位，抬起后可复用。Windows 批量注入同一帧的活动触点，断开时取消仍按住的触点。

Windows 发送端和签名 HAP 已构建，离线检查覆盖旧格式、两触点同帧、先后抬起、取消和非法帧。

首次真机复核中，D3D11 设备创建成功，DXGI 桌面复制返回访问拒绝，尚未建立串流。测试退出后恢复原显示布局、清理转发并恢复旧版 HAP。日志保存于 `.local/daily-tests/multi-touch-223857/`。

第二次在 Windows 桌面会话中建立了 USB 扩展串流。用户在测试窗口中点按，再用双指拉开。Windows 测试窗口记录 `NATIVE_SINGLE_RELEASE`、`NATIVE_TWO_CONTACTS` 和 `NATIVE_PINCH_ZOOM`，原生缩放结束后窗口自动关闭。运行证据保存在 `.local/daily-tests/multi-touch-224053/`。测试退出后回到原单屏布局，HDC 转发列表为空。新版 HAP 留在平板上，通过复核的发送端已放入 `pc/subscreen_sender.exe`。旧版回滚包和发送端保存在 `.local/multi-touch-build/rollback/`。本轮未单独测试按住两个触点时拔线。

## 桌面静默启动

双击入口把启动交给 Windows Script Host，批处理窗口随即退出。后台使用 `--watch --touch --once`。VS Code 仍运行原守护模式。替身脚本测试覆盖了本机 HDC 入口与默认入口，并验证父命令行退出。

真机以单次会话启动，建立 USB 扩展串流后通过 HDC 停止平板上的 SubScreen。USB 仍连接，Windows 发送端自行退出，虚拟屏和 HDC 转发均已回收。本地证据位于 `.local/daily-tests/desktop-exit-230004/`。

用户随后双击桌面快捷方式，看到画面后拔掉 USB。Windows 日志记录了虚拟屏移除和单次会话退出，现场检查确认发送端已关闭、转发列表为空，显示已恢复单屏。证据位于 `.local/daily-tests/desktop-unplug-230145/`。本轮未测试按住两个触点时拔线。
